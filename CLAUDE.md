# Tyrebiter: notes for Claude Code

Next.js 15 App Router + TypeScript, Supabase (Postgres, Auth, Realtime, Storage), Stripe (ID checks), PayID/bank transfer (optional Azupay), Twilio, Resend. Plain CSS design system in `src/app/globals.css` (bright white + "flavour" colour backdrops, Plus Jakarta Sans + Fraunces italic). Keep that look.

## Where things live
- `supabase/migrations/` – schema, RLS, and the auction engine in SQL. **Money and bidding rules live in the database**: `place_bid`, `buy_now`, `make_offer`, `close_due_lots`, `admin_accept`, `admin_decline_referral`, `price_breakdown`, `create_invoice`. Change rules there, add a new migration file, never edit applied ones.
- `src/lib/fees.ts` mirrors `price_breakdown()` for the live preview (including the per-vehicle transport in the premium). Keep them in step.
- Search: `src/lib/vehicles.ts` (the 10 categories, sub-types, makes and models), `src/lib/search.ts` (filter names, the plain-English parser, typeahead). The database side is `search_pred()` / `search_lots()` / `lot_facets()` and `queue_search_alerts()` in `20261003000006_search.sql`. A new filter needs all four: `FILTER_KEYS` + `cleanFilters`, `search_pred`, the alert sweep, and `SearchFilterPanel`. `search_pred` builds SQL from fixed text only; values are always read from `$1`.
- `src/lib/charges.ts` – when an invoice is created: bank invoices (`pay_method` 'bank') just move to `deposit_paid`/`paid` (`finishBankInvoice`); old card invoices are charged off-session.
- `src/app/api/cron/process` – every-minute clock.
- `src/content/legal.ts` – Terms, Help and Privacy copy (draft, needs legal review).
- Admin UI: `src/app/admin`, vehicle editor `src/components/LotEditor.tsx` (writes directly with the browser Supabase client; RLS allows admins).

## Rules
- Private data (reserve, leader's max, seller details) is in `lot_private`, admin-only. Never expose it in public queries.
- Members can't change verification/payment/role fields on `profiles` (trigger `protect_profile`). Server routes use the service-role client for those.
- Test mode: `NEXT_PUBLIC_TEST_MODE=true` fakes SMS (code 123456), ID, charges and (with deposits on, via `/api/deposit/test`) a deposit arriving.

## Scale rules (tested at 1M accounts; keep them)
- Public data is read through `src/lib/cache.ts` (unstable_cache + cookie-less client). Don't query public data per request with the session client.
- Live prices: Realtime **Broadcast** on `lot:<id>` (trigger `broadcast_lot`) + `/api/lots/[id]/live` (edge-cached 1 s). Never `postgres_changes`, never `router.refresh()` per bid.
- Alerts: queue with `queue_notice` / `queue_notice_many` / `queue_seller_notice` (SQL) or `notify()` (TS); the sender is `drainOutbox`. Never call Twilio/Resend inline in a loop.
- Charging: `claim_invoice_charges` + Stripe idempotency keys (`src/lib/charges.ts`). Never charge an invoice that wasn't claimed. Bank invoices go through the same claim.
- Row-level security uses `(select auth.uid())` / `(select public.is_admin())` so it's evaluated once per query. Index every new filter column.
- `npm run test:db` must pass; for big changes re-run `tests/load` (see README).

## Seller side
- `sign_seller_agreement` (server only) links `lots.seller_id`, stores disclosures, reserve, finance. `lot_publish_check` blocks going live until agreement + seller ID + ownership + VIN/PPSR (setting `selling.require_checks`).
- `bid_guard` blocks sellers (and their mobile) from bidding, and requires the current terms version.
- Payouts (`seller_payouts`) are created when an invoice is paid in full, held by open claims, released by `release_payouts()` after collection + claim window.
- Sell form (`/sell`, `src/app/sell/SellForm.tsx` → `POST /api/sell`, migration `20261011000016_sell_form.sql`): rules in `src/lib/sellForm.ts` (`validateSell` runs in the browser and on the server; `QUESTIONS` are the agreement's yes/no questions, also used by `AgreementForm`; `TRANSMISSIONS`/`FUELS` stored in the listings' own words). Appraisals are server-insert only (no anon policy). Photos: browser-shrunk, into private `appraisal-photos` (images only, 12 MB). Signature: `SignaturePad` keeps strokes as numbers (600 wide, height from the pad's shape), `cleanSignature` checks them, `signatureSvg` draws them; never store a picture the browser sends. Server uploads to storage send bytes (`TextEncoder`/`Uint8Array`), not a `Blob` (that becomes multipart). The signed copy is `sellerAgreementPdf` in `src/lib/pdf.ts`; bump `SELLER_AGREEMENT_VERSION_LABEL` with the agreement text. Admin "Create draft listing" copies answers, reserve (`lot_private.reserve_price`) and finance (private); the agreement page prefills from the appraisal with `agreementPrefill`.
- Watchlist (`/watchlist`, `src/components/watchlist/WatchBoard.tsx`): Broadcast per live lot (soonest 40) + `/api/lots/[id]/live` re-checks; quick bid uses the shared `BidConfirm` (same confirm step as `BidPanel`); every live price shows its all-in (`lotFees` + `priceBreakdown`). Global `.done` and `section` styles exist, so don't name a class `done` or rely on bare `section` spacing.

## Listings: photos, videos, bidders, consultants
- Gallery (`src/components/Gallery.tsx`, app `mobile/src/ui/Gallery.tsx`): big photo plus four, "+N", full-screen viewer, credits (`lot_photos.credit`/`credit_url`). Never fill listings with photos from other sites; `scripts/sample-photos.mjs` uses openly licensed Commons photos with credits.
- Videos (`20261003000008_media_partners.sql`): sellers/admins get a signed upload URL (`/api/videos/upload-url`) into the private bucket `video-uploads`, then `/api/videos` checks the file with `storage.info()` and calls `request_lot_video`. Admin approval (`approve-video` in `api/admin/[action]`) publishes it to the public bucket `lot-videos` through `publishVideo`, which first blanks the place the phone recorded (`blankLocation` in `src/lib/mediaPrivacy.ts`, byte for byte, range reads). Listing photos are redrawn in the browser before upload (`cleanPhoto`, `src/lib/photoPrep.ts`), which drops EXIF and GPS. No storage policies: all storage access is server-side. Orphan uploads are removed by the clock (`video_orphans`).
- Bidder names are never public: `bid_history` / `seller_lot_bids` return `bidder_mask` (a made-up name from a salted hash; salt in `app_secrets`, `bidder_mask()` not executable by clients). Shown blurred with `BlurName`. Don't add real names or per-member suffixes to any public payload.
- No viewings (since migration `20261022000021_depot_collection.sql`): buyers never go to the seller's place. `request_viewing` refuses (`viewing_not_offered`), constraint `lots_no_viewings` keeps `in_person_viewing` false, `/api/viewings` answers old app versions, `src/lib/viewings.ts` only has the refusal words. Listings show "How to check it." (`CHECK_IT`/`NO_VIEWINGS` in `src/lib/transport.ts`, web and app). Mechanical inspections are partner leads (kind `inspection`, `MechanicalInspection`; the mechanic's email gets only the area of the pickup address, staff arrange access), or the listing's consultant (`consultants`, `lots.consultant_id`, one default). Never test drives, video calls with the seller, or the seller's details to a buyer.
- Inspected listings: `lots.inspected_at/inspected_by/inspection_summary` (badge, search filter `inspected`), report PDF in private bucket `inspection-reports` (`lot_private.inspection_report_path`, served by `/api/lots/[id]/inspection-report` to signed-in members only). A seller can choose an inspection before listing (`lot_private.pre_inspection_requested`; fee `selling.pre_inspection_fee` locked into `seller_agreements.fees`, taken in `on_invoice_paid` as `other_deductions`, nothing if unsold).
- Up to 10 photos and videos per listing, one of them a video (`lot_media_count`, trigger `lot_photo_limit`, `request_lot_video`; `MEDIA_MAX` in `src/lib/videos.ts`). Staff uploads from the editor are published straight away (`publishVideo` in `src/lib/videoPublish.ts`).
- Every listing is `registration` 'registered' (plate, state, current expiry) or 'unregistered' (sold without plates); `lot_publish_check` enforces it. Search filter `rego`.

## How money is taken: no cards; no deposit by default; non-payers banned (migration `20261012000017_bidding_deposits.sql`)
- Settings `fees.pay_mode`: 'transfer' (default, like Turners: `can_bid` needs only details + verified mobile + verified ID; invoices are `pay_method` 'bank' with `deposit_applied` 0 and the whole amount due by transfer) or 'deposit' (below). 'card' is the old way, kept for old invoices, not selectable. `payMode()`/`priceBreakdown` in `src/lib/fees.ts`; wording helpers `winPayLine`/`buyNowPayLine`/`ackPayLine`/`joinSteps` in `src/lib/deposits.ts` (web and app).
- Bans: `ban_member(user, reason)` (suspends with `suspended_reason`, stores salted one-way hashes of name+DOB, mobile (last 9 digits) and email in `banned_identities`, removes their live bids via `admin_remove_bidder`, lapses offers); `unban_member`. Trigger `zz_profile_ban_check` suspends a new/changed account that matches once its ID or mobile is verified. `bid_gate()` raises `account_suspended` (friendly message) before `not_verified`. `cancel-invoice` bans automatically; Admin → Members has Ban / Unsuspend.
- Deposit mode details: Rule `deposit_for(amount)` = least(greatest(min, ceil(amount × rate)), cap) from `fees.deposit_rate/min/cap` (global, never locked per vehicle: `lot_price_breakdown` and `lotFees` skip them). TS mirror `depositFor`/`bidLimit`/`priceBreakdown` in `src/lib/fees.ts`; words and helpers in `src/lib/deposits.ts` (shared with the app); keep all three in step.
- Ledger `bidder_deposits` (the balance is the sum; kinds received/applied/returned/withdrawal/adjustment; members read their own, only the server writes). `deposit_committed` = deposit for each live lead at max(leader max, current bid), referred leads, open offers. `deposit_check` (in `place_bid`, `buy_now`, `make_offer`, `respond_second_chance`, after the lot lock, with an advisory lock per member) raises `deposit_short:<need>:<free>` → API 402 via `failBid`, shown by `DepositShort`. `can_bid` needs the minimum.
- Win: `create_invoice` applies least(deposit for the price, balance) as an 'applied' row and sets `pay_method` 'bank', `deposit_applied`. Default: `cancel-invoice` keeps it (half to the seller as a `forfeit` payout). Not the buyer's fault: `return_invoice_deposit`.
- Money in: `record_deposit` (admin page `/admin/deposits`, test route, or the Azupay webhook `/api/payments/azupay` with `provider_ref` so it counts once). The payer's name must match the member (`payerMatches`; admins can confirm a joint account). Money out: `request_deposit_withdrawal` (not while an invoice is unpaid; refunds go only to the account it came from), `deposit_withdrawal_paid` / `cancel_deposit_withdrawal`, corrections `adjust_deposit` (reason needed). `my_deposit()` for the member's page; `deposit_totals()` for admin.
- Single-use PayIDs: `src/lib/payid.ts` (off unless `AZUPAY_*` are set), `payment_requests`. Our account details come from `NEXT_PUBLIC_BANK_*`/`NEXT_PUBLIC_PAYID`; `PayBox` (web) and `PayRows` (app) always show the scam warning.
- UI: `/account/deposit` (`DepositHome`, the "paddle"), join step 4 (after ID, so steps run 1,2,3,5,4), `DepositPay` (limit chips → exact amount, reference, "I've sent it" polls `/api/deposit`), `DepositNeed` under bid boxes, the invoice balance box. App: `mobile/src/app/deposit.tsx`, `mobile/src/ui/Deposit.tsx`.

## Pickup to our depot, collection there, the seller kept private (migration `20261022000021_depot_collection.sql`)
- Vehicles stay with their owners until paid for; buyers collect from a depot. `depots` (public: name, suburb, state, postcode, hours) and `depot_private` (street address, phone, email; admin only; written by `depot-save`, page `/admin/depots`). `lots.depot_id` copies the depot's suburb/state/postcode into the lot (trigger `lot_a_depot_location`, which runs before `lot_corrections_log`; `depot_moved` follows depot edits), so every public place is the depot's, never the seller's. The pickup address is `lot_private.seller_address` (+ `pickup_notes`).
- Transport is in the buyer's premium: `lots.transport_fee` (before GST) goes into `lots.fees.transport` when bidding opens (`lot_fees_snapshot`; `lot_transport_lock` refuses changes after that). `price_breakdown_with` adds it to the premium (GST on all of it), `invoices.transport` records it, listings without the key carry 0. TS: `priceBreakdown`/`lotFees` (`src/lib/fees.ts`), labels `premiumLabel`/`collectLine` (`src/lib/transport.ts`).
- After payment `start_ownership_transfer` also creates a `transport_jobs` row (ref TR-#####): to_book → booked → picked_up → at_depot → released (or returned/cancelled). Staff steps go through `admin_transport` (page `/admin/transport`, admin actions `transport` and `transport-send`, which emails the partner/depot the pickup with the seller's address, marked confidential). A change the driver notes at pickup: the buyer answers on the invoice (`transport_decision`, `POST /api/transport`); cancelling is a full refund. `collection_ready()` decides when `collect_by` starts (paid, transfer complete, at the depot, no unanswered change); trigger `collection_needs_depot` (before `collection_needs_transfer`) blocks bookings until then; no storage before it.
- Buyers see `invoice_transport()` (the depot's street address only once a collection time is confirmed), sellers `seller_lot_transport()` (never the buyer). `confirm-collection` sends the buyer the depot's address and release code and the depot its handover link (`collections.seller_token`, `/handover/[token]`); `collection_released` marks the pickup released. Wording: `buyerTransportLine`/`sellerTransportLine`/`transportError` in `src/lib/transport.ts` (shared with the app).
- The seller is never identified to a buyer: no seller name, address or phone in any buyer page, API, notice, PDF (`Tyrebiter, as agent for the owner`) or partner email other than the transport booking. The agreement form's section 2 collects the pickup address and the four `SELLER_ACKS` (`src/lib/sellForm.ts` → `seller_agreements.acknowledgements`), checked again by `/api/seller/sign`.
- Terms sections 2, 4 (statutory warranty), 5 (no viewings, inspections), 7 (transport), 9 (risk: the seller until pickup, us until handover), 14, 16 (collecting from our depot) and 18 (leave the seller alone), and seller agreement sections 1, 3, 7 and 15 describe this. Change them with the engine.

## Phone app (`mobile/`)
- Expo SDK 57 + expo-router (`mobile/src/app`), iOS and Android from one codebase. Store steps and listing copy: `mobile/README.md`, `mobile/store/LISTING.md`.
- It imports the website's `src/lib` (search, vehicles, fees, format) through Metro `watchFolders` and the `@/lib/*` path. Keep those files free of Next/Node-only imports. Root `tsconfig.json` and `eslint.config.mjs` exclude `mobile/`.

- Push: `push_devices` table, `POST/DELETE /api/push`, trigger `notifications_push` queues 'push' outbox rows, `src/lib/push.ts` sends via Expo (100 per request). `PUSH_DISABLED=true` skips sending. New alert kinds need a `push_wanted` rule and an Android channel (`bids` or `updates`).
- Account deletion (store rule): `/api/account/delete` + `delete_account()` / `account_deletion_blockers()`; public page `/delete-account`.
- Universal links: `src/app/.well-known/*` (env `APPLE_TEAM_ID`, `ANDROID_CERT_SHA256`). App paths are listed in `mobile/app.config.ts` (APP_PATHS) and the AASA route; keep them in step with `mobile/src/lib/links.ts`.
- Forced update: settings key `app` (`min_ios`, `min_android`), served by `/api/app/config`.
- Checks: `cd mobile && npm run typecheck && npm test`; `npx expo export -p ios -p android` must bundle. The web build (`npx expo export -p web`) is what the end-to-end tests drive.

## Live auctions, tenders, BPAY, damage map, calendar (migration `20261021000020_live_tender_bpay.sql`)
- One bidding engine: `place_bid_for(user, lot, max, source)` (service only) does the work; `place_bid` (members) and `admin_floor_bid` (auctioneer, by bidder number = `deposit_ref` or BPAY CRN) call it. `bids.source` is 'online' or 'floor'. Never add a second bidding path.
- Live sales: `sales.mode = 'live'` (+ `starts_at`, `lot_seconds`, `extend_seconds`, `stream_url` (YouTube/Vimeo player only, checked by the DB and `streamEmbed` in `src/lib/live.ts`; CSP frame-src allows only those), `auctioneer`, `auto_advance`, `live_status` scheduled/running/paused/ended, `current_lot_id`, `live_message`). Lots in a live sale get `lots.live_state` waiting/open/closed (trigger `lot_method_rules`; a timed lot with bids can't move in). Waiting lots take early bids, never extend, and their `ends_at` is an estimate kept in the future by `live_estimates` (clock `live_sweep`); `close_due_lots` skips them. Opening a lot (`live_advance`) sets a short countdown; bids reset it to `extend_seconds` (`bid_extends_auction`). Console steps: `admin_live_start/next/message/pause/resume/time/close/end`, `admin_sale_order` (all via `POST /api/admin/live` with `op`). Broadcast `sale:<id>` (trigger `broadcast_sale`) + `lot:<id>`; room data `/api/sales/[slug]/live` (edge 1 s, `src/lib/liveRoom.ts`). Pages: `/live/[slug]` (`LiveRoom`), console `/admin/live/[id]` (`/api/admin/live-room/[id]`), app `mobile/src/app/live/[slug].tsx`.
- Tenders: `lots.method = 'tender'`: sealed amounts in `max_bids` only (no `bids` rows, nothing on the public price, `tender_count` public), no extension, no Buy Now; `withdraw_tender`; `reveal_tenders()` (called by `close_due_lots`) makes the top tender (earliest on a tie) the price, then the normal close. Tenders count toward the bidding deposit. A tender is "bought outright" for consumer rights (`consumerRights("outright")`). UI `TenderPanel` (web), `mobile/src/ui/Tender.tsx`.
- `close_one_lot(id)` is the single close rule (sold / referred / offers / passed); use it, don't copy it.
- BPAY: `profiles.bpay_crn` (MOD10V01 check digit, `bpay_check_digit`, mirrored by `src/lib/bpay.ts`), protected from members. Biller code `NEXT_PUBLIC_BPAY_BILLER` (`payBank()` in `src/lib/env.ts`); `PayBox`/`PayRows` show BPAY only when it's set. Staff record deposits by CRN (method 'bpay') and find invoices by TB-/BID/CRN on `/admin/invoices?ref=`.
- Damage map: `lot_flaws.zone` (list in `src/lib/damage.ts` = the DB check; car's left = passenger side, drawn on the left). `DamageMap` (web and app).
- Search filters `wo` (clear/writeoff) and `how` (timed/live/tender): all four places plus the app's FilterSheet. Calendar: `auction_calendar()` (public, in the allowlist) → `/calendar` and `/calendar.ics` (`src/lib/calendar.ts`).
- Terms section 6 has the live (`#t-live`) and tender (`#t-tender`) rules; change them with the engine.

## Security (migration `20261012000018_security.sql`; keep it)
- `is_admin()` is true only for an admin whose session passed two-step (JWT `aal` = 'aal2') while setting `security.admin_mfa` is on (default). Every admin rule goes through `is_admin()`; never check `role = 'admin'` for permission. `admin_access()` → 'no'/'mfa'/'ok'. Pages use `requireAdmin()` (sends 'mfa' to `/security/two-step`), API routes `adminApi()` then `audit(...)` (`src/lib/admin.ts`). Two-step page: `src/app/security/two-step` (Supabase MFA TOTP).
- `admin_audit` is append-only (triggers block update/delete/truncate); the server writes with `audit_admin` (service only), direct admin writes are logged by trigger `zz_audit_admin` (add it to new admin-edited tables). `auditDetail` (`src/lib/redact.ts`) hides secret-looking fields. Role changes alert every admin (`profile_role_alert`). Page: `/admin/security`.
- Public settings are only the keys in policy `settings_read`. Security definer functions are closed to PUBLIC/anon except `public_function_allowlist()`; a new public one must be added there and to `ANON_OK` in the DB test, or the test and Site health fail. Revoke new privileged functions from public and anon.
- Headers and CSP in `next.config.ts`: a new outside script, image, frame or API host must be added to the CSP. Cross-site POSTs with a sign-in cookie get 403 (`crossSite` in `src/lib/csrf.ts`, run by the middleware on `/api/*`). Redirect targets from the address bar go through `safePath`. Cron secret only in the `Authorization` header (`authorised` in `src/lib/cron.ts`, constant time).
- Never put user-supplied text into `dangerouslySetInnerHTML` without escaping (`fillLegal` escapes settings values). Rate-limit new public or SMS/ID-costing endpoints with `allow`.
- CI: `npm audit --omit=dev --audit-level=high`, gitleaks (fake test keys go in `.gitleaksignore`), CodeQL (`codeql.yml`), Dependabot. Unit tests `tests/unit/security.test.mjs`.
